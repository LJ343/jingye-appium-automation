# Wireless recovery 0.5.3 — 2026-11-10

The companion can confirm the wireless-debugging network-trust dialog for an access point explicitly enrolled by the user. This handles the separate network approval that can otherwise interrupt unattended recovery. PC pairing remains a separate prerequisite: the helper never creates a new PC pairing, removes existing pairing records, or approves an unknown network.

Enrollment requires foreground precise-location permission and Android location enabled so Android can reveal the current SSID and BSSID. The user confirms that exact combination; only its SHA256 is retained in private preferences, with at most 16 entries. There is no SSID-only match or bulk registration. The user separately enables automatic confirmation in the app and manually enables its accessibility service in Android settings. ACCESS_WIFI_STATE and foreground FINE/COARSE_LOCATION are added relative to 0.4. No background-location permission, GPS coordinate collection, MANAGE_DEBUGGING or gesture capability is added.

The accessibility adapter requires platform-signed SystemUI, an unlocked interactive screen, a live armed recovery service, an eligible focused/active window, unique complete controls and exact localized system-resource labels. It accepts the Android message template and the complete Honor split SSID/BSSID layout. Honor application-type bottom dialogs are supported only with the full verified layout. Unknown layouts, owners, APs, duplicate controls, locked screens and missing identity fail closed. There are no coordinate/gesture fallbacks in the shipped helper. The AP, dialog, window and checkbox state are checked again immediately before every action. Clicking always-allow and clicking allow are separate actions.

0.5.3 selects the actual active root and window metadata instead of treating an accessibility event window ID as the target. Transient or missing event IDs after the checkbox no longer discard the pending confirmation. The short follow-up remains bounded to six inspections and eight seconds; replacement windows inside that burst do not replenish its budget. A separate persisted ledger permits at most three checkbox and three allow actions per ten minutes; duplicate AP/window/action combinations and storage or clock faults block actions. A click-sent diagnostic is not proof of PC connectivity.

The existing 0.4 switch recovery remains byte-identical: at most two additional attempts after 60/120 seconds, with persistent episode/global budgets and hard protective stops. Original authenticated address reporting remains at most once per 15 seconds while armed, on Wi-Fi and with the switch enabled. The PC reuses a healthy connection and discovers/reconnects on demand. Desktop configuration, discovery range/budget, collection, dates, database, uploads, email, scheduled entrypoints, official code and USB main are unchanged.

See NETWORK_TRUST_VALIDATION.json for the exact installed artifact, known-AP dialog acceptance, current saved-PC-key check and offline counts. Offline source tests include 250 Python cases, 41 switch-policy cases, 9 real StateStore cases, 56 trust-policy cases, 14 real TrustSettings storage cases, 9 window-session cases, 12 protocol assertions and the shared Java/Python protocol vector. Offline fixtures are outside src and are not packaged. Historical 0.3/0.4 documents and fixtures describe their dated versions.

No new business task, natural roaming, real switch-reset fault, force-stop or reboot recovery is claimed by this release. Screen unlock is never automated. An OS that permanently ends the helper/accessibility service remains outside the guarantee. An ordinary connection failure should trigger reconnect while pairing remains valid; a phone that forgets the PC requires a new explicit user-authorized pairing. Dynamic connection and pairing ports must not be confused or hardcoded. Same-signer upgrades preserve private app data; never uninstall or clear data to update.

Public delivery excludes local device/network identifiers, provisioning material, account data, logs, attachments, signing private keys and SDK dependencies. Rebuilding with a different signing key cannot update this installed APK. The source aggregate includes AndroidManifest.xml, src/**/*.java and res/**/* and matches the installed release artifact's frozen source.
