The accepted phone helper remains 0.6.4, byte-for-byte unchanged. No reinstall, pairing reset or network re-registration is required for this desktop update. USB main and the existing business/cron/WAIT entry are unchanged.

Cleanup reported device offline, leaving creation_unknown. Two later tasks automatically connected to the same phone, but were blocked by that old record before a new Remote. The previous failed-creation classifier required an initialization-failure message, so it excluded this post-initialization transport-loss window. ADB host diagnostics independently show a read failure followed by connection refusal (10061) at the same target endpoint. The phone instrumentation process remained alive. The initiating phone/network reason is not established; port change, trust loss, Wi-Fi roaming and a phone-side instrumentation crash must not be asserted from these facts alone.

The narrow classifier now also accepts an exact launched/initialized request followed by device offline, a completed500, no master addition and no competing mutation. An arbitrary500 or exit255 remains insufficient. Before Remote, the canonical private journal stores the original idle snapshot, baseline forwards, boot/uptime marker, exact request token and birth-matched log identity/header/offset. A later process can restore those original bytes instead of inventing a pre-creation baseline.

Cross-task reclamation requires the old client to be absent, the same Appium host, the exclusive failed terminal, verified physical phone identity and an empty or exact-token downstream session bound to its stable PID/UID/start/name/socket/instrumentation. A remaining process must match the original boot and creation window. Only the exact owned process and newly owned forwards are eligible. Two physical-idle observations precede archival. Original browser forwards remain; new unexplained forwards do not. Known terminal-session reconciliation also preserves forwards proved to predate the creation. Legacy records without durable evidence remain protected.

Each signal and proof-forward allocation/removal writes a durable intent before the command and a confirmation after its response. A later process encountering prior phone mutations can only converge through read-only physical idle proof; it cannot replay a signal or guess removal after a lost response. Remaining uncertain residuals stay protected. Cleanup failures emit fixed private-data-free categories; a refused old guard no longer produces a false released message.
