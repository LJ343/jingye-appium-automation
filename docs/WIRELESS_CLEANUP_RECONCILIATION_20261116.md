# Reconcile unresolved cleanup across clients — 2026-11-16

A phone shutdown or lost wireless link can leave cleanup_uncertain even after Appium has deleted its session: the client could not finish the final physical-idle checks. A later run previously remained blocked despite a reconnected, idle phone. The safety journal remains necessary; this repair adds a bounded, read-only way to re-establish its missing evidence before a new session is reserved.

Only a known UUID session in same-host cleanup_uncertain is eligible. The canonical journal lock remains held while checking that the original Windows client is absent (or its PID has provably been reused), the freshly queried Appium PID and birth time match, and a unique birth-matched startup log has a complete paired master lifecycle with no active or pending sessions. The exact old session must have one completed DELETE 200 in that log and independently return W3C invalid session id from its known-session GET. GET /sessions 404 and the generic status endpoint are never treated as proof of an empty host.

The existing wireless client verifies the configured phone identity again. Two equal physical snapshots must each show zero UiAutomator2 processes, zero test instrumentations and zero forwards. The original-client identity, known-session GET, log tail and host identity are rechecked. Only then is the old record, with its proof, retained in journal history and archived atomically. The caller obtains its new reservation through the ordinary guard again, so a competing reservation still wins safely. This path never signals a process, deletes a session, changes settings or creates/removes forwards.

Creation_unknown, unfinished creation, active records, records without an exact session ID, missing or ambiguous logs, pending/foreign sessions, a live original client, any physical residue, changed phone/host/transport, failed storage, or an exhausted budget retain protection. The entire evidence operation has a 90-second deadline. The startup log is streamed with bounded lines; its subsequent tail is bounded and must contain no mutation. Healthy runs with no unresolved journal do not run this extra audit. This establishes a safe final state; it does not guess that every disconnect was a shutdown or automatically remove arbitrary protection.
